# MensaTogether JSON API

All requests use same-origin `/api`, JSON and session cookies. GET `/api/bootstrap` returns `csrfToken`, `user` (null or `{id,alias}`), `mensas` (`id,name,hours,meetingPoints`), `today` (Berlin date), `demoAccounts` (fictional alias/email/password). Mutations require `X-CSRF-Token`. Login does too; fetch bootstrap first. Errors are `{error:{code,message}}` with 400/401/403/404/409/422/429.

- POST `/api/auth/login` `{email,password}` returns `{user,csrfToken}`; POST `/api/auth/logout` `{}` returns `{user:null,csrfToken}`.
- GET `/api/overview?mensaId=eupener&date=YYYY-MM-DD` returns `{mensaId,date,serviceWindows:[{start,end}],hoursVerifiedAt,notice,slots:[{id,time,end,selectable,count,friends:[{id,alias}],publicParticipants:[{alias}]}],menu:[{id,name,description,image,priceInternal,priceExternal,diet,allergens}],menuNotice}`. Slot IDs are `HH:MM`. Closed/past slots are not selectable. Counts include private submissions without identities.
- GET `/api/plans?date=YYYY-MM-DD` returns `{plan:null|{id,date,mensaId,slotId,time,end,meetingPointId,visibility,reminder,reminderStatus,status,version,editable}}`; requires login.
- PUT `/api/plans` `{date,mensaId,slotId,meetingPointId:null|string,visibility:"private"|"friends"|"public",reminder:boolean,version:0|number,requestId:string}` returns `{plan}`. `version:0` creates; subsequent edits require current version. `slotId` must be one scalar time. One row per owner/date. `requestId` is a fresh UUID per intended mutation, reused for uncertain retries.
- DELETE `/api/plans` `{date,version,requestId}` returns `{plan}` cancelled. Mutations after arrival are rejected. No GET mutates a plan.
- GET `/api/friends?date=YYYY-MM-DD` returns `{friends:[{id,alias,sharedPlan:null|{date,mensaId,slotId,meetingPointId}}],requests:[{id,alias}],outgoing:[{id,alias}]}`. Null sharedPlan means neutral `No shared details`, without revealing private existence.
- POST `/api/invites` `{}` creates `{code,expiresAt,url}`. The code is opaque, single-use, 24 hours; URL is a friendship code deep link. GET `/api/invites?code=...` previews `{alias}` only. POST `/api/friends` `{code}` requests friendship. POST `/api/friends/accept` `{id}` accepts incoming request. DELETE `/api/friends` `{id}` removes it. DELETE `/api/invites` `{code}` revokes own code.
- POST `/api/push/subscriptions` `{endpoint,keys:{p256dh,auth}}` registers the current browser push subscription when server delivery is configured. DELETE the same endpoint with `{endpoint}` unregisters the owner's browser. GET `/api/push/config` returns actual delivery capability (`supported`, `publicKey`). Older `/api/reminders/subscription` and `/api/reminders/status` aliases are retained. No browser-only timer is claimed to work with the browser closed.

Menu content and evaluation accounts are explicitly fictional/sample data. Hours are verified regular schedules as of 2026-11-05, with maintained date-specific closures, not live operator status. Public plans expose alias only, never private IDs, meeting points or reminder preferences. Authenticated endpoints return owner data only; accepted friends see only explicitly shared plan details.

The generated slot policy is the source of truth rather than a mutable slot table. Static mensas and meeting points are code-owned configuration; date-specific exceptions are in `backend/database/closures.json`. North Rhine-Westphalia public holidays and weekends default to closed, subject to explicit operator-confirmed overrides. Hours are regular published schedules, not a live-status guarantee. Sü​dpark is deliberately excluded until its closure status can be verified.

Fictional accounts use `alex@example.test`, `sam@example.test`, and `jules@example.test`, password `CampusLunch!2026`. They start without fabricated lunch plans or friendships. Seed reruns never reset passwords, plans or relationships. Public sharing explicitly opts the evaluation alias into the public response. Sample menu `diet` is `Unverified`; empty allergen arrays mean unknown, not allergen-free.
